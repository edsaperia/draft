# draft — project conventions

A group drafting engine: patches race, blind pairwise judgments rank them, adoption clears a rising confidence bar. SPEC.md is the source of truth for the mechanism; when spec and code disagree, the spec wins until Ed amends it.

## Documents

- `SPEC.md` — the mechanism spec, and the single source of truth. Amend only with Ed's sign-off; bump the version. No separate decision log: resolved decisions are folded into the spec ("keep latest design, not history" — Ed, 2026-08-13).
- `QUESTIONS.md` — open and deferred items only, numbered from one continuous project-wide sequence (Ed answers by number). Never renumber or reuse numbers; delete items once folded into the spec. Questions raised in chat that Ed doesn't answer before the session ends belong here with real sequence numbers — otherwise they die in the transcript. Draw in-chat numbers from this sequence too when they concern project decisions; ad-hoc chat numbering collides with it and makes the record ambiguous (learned 2026-08-15).
- `design/*.html` — the mockup series (race-card, session-view, composer): single static files, light-only, Bootstrap-plain, shared palette and one continuous fictional world (the Hollow Oak Club charter). Each carries its own design notes and named-parts glossary at the bottom — except `session-view`, whose notes moved to `design/session-view.notes.md` on 2026-08-15 (Ed, 76: nothing sits underneath the three-column view). Keep new surfaces consistent with the series.
- `packages/sim-harness/REPORT-deferred-evidence.md` — findings from the 2026-08-14 evidence pass (Q8/Q9/Q10/Q13), with reproduce instructions.

## V1 product decisions

- Target context: constitutional conventions for Newspeak House cohorts. Rosters typically 5–10, conventions 15–20; design must not preclude 100+/1000+ instances, but v1 tunes to small rosters (data-efficiency over throughput).
- Hosted multi-tenant web service; magic-link auth against roster emails.
- Documents are Markdown, rendered as rich text; usually a few pages, long-document behavior stays in scope for sim experiments.
- TypeScript end-to-end; engine-core is a pure, dependency-free library shared by sim-harness and product server.
- Sim personas are LLM-powered on a cheap model (Haiku-class) and speak the same participant API as human clients — no sim backdoor; mixed human/bot sessions are a goal.

- UI north star (Ed, 2026-08-14): **suggestion-mode with escalation** — the default surface reads like familiar Google-Docs-style inline suggestions with approval; the race view (overlay model, pairwise cards) is the escalation state that appears only where suggestions collide or stakes demand ceremony. Most of a session should feel like approving typo fixes; the machinery earns its visibility.

## Glossary — named parts

Use these names in all discussion, commits, and code. Literal and stable beats elegant.

**Engine (mechanism, no UI):**
- `engine-core` — session state machine: candidates, races, adoptions, the adoption-threshold ramp, tokens/refunds, adoption floors, certification.
- `adoption-threshold` — the confidence bar a challenger's win-probability must clear; ramps over the session window (wall clock). Formerly "θ"; always use this name.
- `patch-engine` — text machinery: diffs, footprints, three-way merge, rebase, surgery.
- `overlap-gates` — the three-gate classifier for colliding patches: textual composition → semantic composition → rivalry.
- `ranking-model` — Bradley–Terry preference model (per race) + global salience model, with active pair sampling and deadlock detection.
- `router` — v/c_p feed ordering, hot set, exploration/salience streams, floors-aware serving, notification digests.
- `event-log` — append-only hash-chained log, seeded RNG, participant receipts.
- `dedup-gate` — submission-time duplicate check (embeddings, edit distance, LLM equivalence) plus behavioral dedup probes.
- `race-labeler` — advisory naming and typing of disputes: a name ("treasurer oversight") and a type (copy-edit · substantive · structural) per race, from the oracle's `describeRace`, with a deterministic nearest-heading + excerpt fallback. Outside the state machine — labels never enter the event log or gate anything; type is stored but not yet wired to routing (Q49).
- `document-modes` — two **independent** settings, both fixed at creation (SPEC §9.0). **Window**: an end datetime, or none (perpetual). **Threshold shape**: fixed, or ramping. A windowed document may hold its bar fixed; only a perpetual one is *constrained*, since a ramp needs an endpoint to ramp toward. A window gives you the closing ceremony and a drip paced against it; without one the drip runs against real time and the document ends by `freeze` instead.
- `founding-ceremony` — the stage before any drafting where the roster sets quorum and threshold: each member states, blind, the *lowest they will accept*, and the document takes the **maximum** of each. A consent rule rather than a vote, which is what lets it escape the constitutional bootstrap — there is no vote to govern, because the result satisfies every stated minimum by construction. Distribution published without names (SPEC §9.0a).
- `sign-out` — a member declaring they are done, choosing **holding** (they stay in the quorum base, so enough of them freezes the document — *I do not consent to you finishing without me*) or **abstaining** (they leave the base — *I trust you to finish up*). Plain silence is never sign-out; judgments already cast keep counting afterwards; the base is the whole roster minus abstainers, never the active remainder (SPEC §9.5).
- `freeze` — what happens when active plus holding falls below quorum: races park, participants are notified, the record is cut. A stall with an alarm, not a death — it thaws if enough return, and it is the perpetual mode's equivalent of a close.
- `coherence-auditor` — machine participant patrolling document drift, fixed token budget.

**Design system (session-view, tokenised 2026-08-16 — the composer should adopt it rather than invent its own):**
- `wash` — the lifecycle colour on any surface that carries one: a clause, a `clause-head`, a held-open gap, a queue entry. **Colour changes fade** rather than jump, over `--wash-ms` (700ms), because a wash changing means something happened and a jump leaves the reader to notice it after the fact (Ed, 2026-08-17). Two things make that work: a queue entry's wash is painted as a **bar** (a `::before` whose width is the fill and whose background-color is the hue) rather than as a hard-stopped gradient, since no browser interpolates between two gradients; and because both rails are rebuilt wholesale on every render, each washed element is rendered wearing its **previous** colour and handed the new one after one forced reflow — keyed by what the wash is *about*, which is why a clause and the head of the card that swallows it share one key and opening a card deepens the colour rather than repainting it.
- `me` — the user avatar at the right of the topbar. Initials, not a photograph: there are no accounts behind it yet. It is the only face on the surface, since everybody else's authorship is sealed (SPEC §3.4) — Q278 asks whether that stays true.
- `lifecycle palette` — six hues held as raw RGB channels: `--lc-urgent` 🔥, `--lc-open` 💡❌, `--lc-weigh` ⚖️ (pink, Ed 2026-08-17), `--lc-deciding` ⏳, `--lc-yours` ✏️ and your own live 💡, `--lc-closed` ✅❎🔄☑️. Two rules now. **Colour means you can still affect it; grey means the door is shut.** And **hot for actions, cold for information** (Ed, 2026-08-17) — orange and yellow are the states that want something from you, blue and grey are the ones telling you where things stand. That second rule is what placed the diagonal: it wants a judgment, so it must be hot; it is a different *kind* of judgment from a proposal, so it must not be the same hot as one. Applied identically to the queue card's wash, the paragraph's wash and the gutter mark. Green is available in a margin only because every *decided* state washes grey there — `--ok`'s green never leaves a card interior, and the two must not be allowed to meet (Q264).
- **Open is said by depth, not by outline** (Ed, 2026-08-17): no active box carries a border — not the decision card, not the drafting box, not the open rail entry. `--shadow-xl` is the only step allowed to be big, and it is still a light source rather than a halo (offset grows with blur, blur near 2.5x it, contact shadow keeping the near edge crisp). This retires 198’s one-blue-for-every-card as a *boundary*; the accent survives as an accent.
- `--primary` — the one accent: every wire, every selection, every control that is on. `--ok` — green, meaning *decided* and only that.
- type scale `--t-lead / --t-body / --t-ui / --t-small / --t-cap / --t-micro`; the `.eyebrow` class carries the single upper-case label treatment.
- spacing `--s1`–`--s5` on a 4px grid; radii `--r-sm / --r-md / --r-lg`; elevation `--shadow-sm/md/lg/xl`, neutral never tinted, and since Ed's QA of 2026-08-16 a **drop shadow rather than a glow** — each step is a 1px contact shadow plus one soft cast whose blur stays near 1.6× its offset, not Bootstrap's 3rem halo — **darker and less diffuse** since Ed, 2026-08-17, because once depth had to carry *open* on its own a wide faint cast became the halo the retune had removed; layout constants `--rail-left / --rail-right / --nav-h`.

**Product (UI and ceremony):**
- `document-creation` — the screen where every §9.0 setting is chosen when a document is made. Ed called it the "draft creation screen"; **`draft` already means a candidate patch** everywhere else in this project, so the surface is `document-creation` and the thing it makes is a document or a charter. Ed wants to see every option on it before any are cut (Q259).
- `edit-wallet` — tokens drawn as ✏️ glyphs, one vanishing per use, the next inking in as the drip accrues: a token *is* an edit, so the wallet says what it buys without a word. **Above four it counts rather than draws** (`✏️✏️✏️✏️+5`), because glyphs are only good at *a few* and a longer row is a bar chart nobody asked for in which a single spend is invisible; and the tray now says **when** the next one lands rather than how far off it is, which is the question anyone standing at an empty wallet is actually asking (Ed, 2026-08-17). Since the composer landed it actually moves — Propose spends one, Withdraw returns it. Note Q251 — at v1 defaults members still sit near the cap, and a visibly depleting wallet reintroduces friction the economy does not require.
- `session-view` — the default member surface: the charter, readable top to bottom, with every contested clause marked where it bites and the `needs-you-queue` beside it. Design: design/session-view.html; reasoning in design/session-view.notes.md, which opens with the current design system. Its zones:
  - `contents-rail` (left) — the charter's own headings, following the reader, adopted sections only. Carries no explanatory note (Ed, QA 2026-08-16: both rails' notes were design notes printed inside the design). Each heading carries the **lifecycle marks** of the questions inside it (innermost ownership, capped at four, keeping whatever is still actionable and dropping ☑️ first); a heading holding exactly one question opens it on click. Scrolls inside itself, scrollbar hidden.
  - `needs-you-queue` (right) — a **margin index**: every entry stands beside its own clause in document order, so *where* an entry sits is never a claim about importance. Entries that still **need you** are pinned on screen (at their clause while it is visible, piled against the band edge once it is not, always in document order, with an overflow count when more exist than fit). Judged lines and sealed dots stay with their clauses, scroll away, and step around a pinned card rather than hiding under it. **Which** of them fit is decided by urgency, most urgent first — a ranking over *admission*, never over position, and never a threshold: nothing is too unimportant to appear, the rail simply runs out of room, and the next ones down surface as the urgent ones are dealt with. The most urgent card (🔥) and whatever is open are exempt from the fit cap, and **the open entry's claim on its clause's line is absolute** — entries that cannot fit around it are dropped into the count rather than displacing it, so its wire reads flat (222). Entries not asking for a judgment cannot be ranked on judgment leverage: an unacknowledged decision takes the middle of the scale, and a `deadlocked` race is ranked instead by its **bounty score** near the top — judgment leverage there is nil precisely because drafting leverage is the highest on the surface (223).
  - `lifecycle mark` — one glyph per entry, the same alphabet in all three columns (contents rail, document gutter, queue): 💡 a proposal, and it wants your judgment · 🔥 wants you most · ❌ stuck, wants a draft not a judgment (its action is ✏️) · ⚖️ a salience diagonal, wants a ranking not a judgment · ⏳ you have judged, still running · 🔄 ground shifted, comes back rebuilt · ✅ decided, charter changed · ❎ decided, incumbent held · ☑️ filed. 🔥 means *an ordinary judgment that wants you most*, so ❌ and ⚖️ are never it. **✏️ means *you wrote this*** — the writing action on a button, and the mark on anything of your own from the first keystroke to the seal, proposed or not (Ed, 260: it stays ✏️ rather than becoming 💡 once proposed, because the contents rail draws marks with no colour and green is what would otherwise have carried the difference). Renamed 2026-08-16 (Ed, 241): a rail entry is somebody's proposal rather than a question the system invented, and promoting the action to its own glyph puts each nearer its job — a bulb is about having had an idea, a pencil is about writing.
  - `yours` — the fifth lifecycle state (Ed, 2026-08-16): a proposal **of your own**, green, from the first keystroke to the moment it seals. It sits outside the judge's ladder, because nothing is asked of you — SPEC §3.3 counts your preference for your own candidate without asking — and it is not settled either, because you can always act on it. ✏️ throughout. Drawn as a **full card while it is an unproposed draft**, so you can read your rationale back as you type it, with a flat wash and **no fill** (there is nothing yet to be close to); **one line once proposed**, with the fill arriving as the completion bar. Never crowded off the screen: it is force-kept beside the flame and the open card, because the rail admits by *judgment* leverage and a proposal of yours scores nothing there while carrying the largest remaining act — withdraw.
  - `salience-diagonal` — SPEC §8.3's ~1-in-10 card, asking which of two open **questions** deserves more of the room's attention. A patch turned inside out: one judgment, two anchors in different parts of the charter, two queue entries joined by a wire spine. Since Ed, 276 it is the **same card as everything else**: its head is the one on the surface that is not a clause (a diagonal has none — it spans two), so it holds the question being put; its field is the two questions, each with its name, its description, the clause it is about quoted underneath, and a *Prefer this*. No `sealed-speaker` on either — the line under each question describes the dispute rather than arguing for it, and drawing a person there would claim an author it does not have. Choosing ranks the questions and never touches either text. It swallows only the clause it stands in, so the far one is quoted while its paragraph is still in the document — accepted by Ed (277). It takes **one** rail entry, not one per clause, standing at the earlier of its two and titled *Prioritise A vs B* (Ed, 2026-08-17), set over four lines — `Prioritise:` / the first name / `vs` / the second (Ed, 284), because on one line the two names collided and truncated, which is the one thing an entry made for weighing them against each other must never do: a patch stands at several places because that is where its work is, but neither clause is where a diagonal lives, so standing at both said "there is something here" twice about a card that is really about the pair.
  - `suggestion-anchor` — a challenged clause wears its queue card's own lifecycle hue and no left rule; the wash deepens on whatever is open. A filed clause washes nothing. Since 2026-08-16 a clause is **not** a button: clicking it puts a caret in it (`always-on-typing`), and the gutter mark is what opens the decision card. `insert-anchor` is a blank held-open gap with 💡 beside it. `chip-gutter` is the left margin the marks stack in, keeping the prose column unbroken. A gutter mark is an **object, not a glyph with a hit area** (Ed, 2026-08-17): a resting ground in its own lifecycle hue, the contact shadow, 30×27 with the glyph at document size, lifting on hover and going *down* on press — the same object the rail's sealed dot already was, since they are one control in two columns. A flatter glyph set is Q288.
  - `decision card` — **the clause, opened.** It *replaces* its paragraph rather than opening beneath it (Ed, QA 2026-08-16; also settles 265), so the thing being proposed about appears exactly once on screen. The shape is a post and its replies: `clause-head` → `proposal-block` for each candidate → commit row, with a hairline between each of the three bands. One card for every type, differing only in what fills the two halves — quick card: clause + one proposal; race: clause + two; patch: the same per site, plus the ↑/↓ stepper; sealed record: clause + the whole field ranked with its numbers. Submitting does not close the card. **Opening**: the card does not grow from nothing — it grows from exactly the height at which only its `clause-head` is showing, so frame one looks like the document with the paragraph still in it, the gap then slides open beneath the clause, and the field fades in 60ms behind the motion. The clause itself never moves (measured 0px on every card type). **Closing runs the card's whole box back onto its paragraph** (Ed, 2026-08-17) — height down to the `clause-head`'s own washed block, padding away, eyebrow shut, lift and white ground gone, and the top edge descending by exactly what it stops holding so the clause still does not move. It used to stop at head height, which is where *opening* starts but is not a paragraph, so the last 93px arrived as a jump; opening gets away with that discrepancy because it happens in the frame of the click, closing put it after the motion, which is the one order the eye will not forgive. The card's own mark closes it — a stale guard had made every mark inside a card inert.
    - `clause-head` — the clause itself at the top of the card, at document size and colour, under an eyebrow. **It keeps the clause's own highlight and its own gutter mark** (Ed, 2026-08-17): the washed block inside it is given the same box as a `.anch` paragraph — same negative margin, same padding — so the wash lands on the same rectangle and the `.chipcol` inside it lands in the same gutter column. Measured: the mark you clicked moves 0px in both axes, and the clause text sits on the prose's own axis to the pixel, which is what makes the card read as the clause opening rather than as something replacing it. The card's mark is the same control it was in the gutter, so it also closes the card; other live suggestions at that clause stack under it exactly as they did beside the paragraph. It carries a `lane-bar` exactly when the judgment can keep the clause: on a quick card or a patch the incumbent is one of the two things being judged; on a **race** both candidates are challengers and nothing on the card can vote to keep it (the adoption-threshold decides that, SPEC §5), so there the head is reference only.
    - `proposal-block` — one candidate: its wording, stating its own change against the clause (see `result-only`); then its rationale behind a `sealed-speaker`; then its `lane-bar`. The reply in the post-and-replies shape, and the reason each argument now sits with its own wording instead of being mapped column-to-column.
    - `sealed-speaker` — the featureless head-and-shoulders disc a rationale sits behind. Ed's note was that nothing said a *person* was saying the rationale; the disc says it, and its blankness says the rest, because authorship is sealed until the record (SPEC §3.4). Drawn rather than left as a plain circle — a bare disc reads as a bullet, and a bullet says *list item*.
    - `result-only` — a proposal states **the text as it would stand**, with what it adds marked green and nothing struck through (Ed, 274, 2026-08-17: *normal people struggle to read or interpret redlines*). This restores 91 and retires the `redline` that briefly replaced it. One rendering everywhere — card, lane and record — so a proposal reads the same wherever you meet it. Two rules survive from the redline: a **marking floor**, below half the new text surviving from the clause the proposal states itself plainly (which is what keeps a race candidate, usually a whole rewrite, from being lit green end to end — Q92); and **punctuation as its own token**, without which a clause that gains a comma marks the whole word. The blind spot it accepts: in a stacked card a proposal whose only change is a *partial* cut looks like the clause above it, and you find it by reading. The worst case is covered — a proposal that removes the text **entirely** would render as blank, which cannot be told from unchanged, so it says *(all text removed)* instead, drawn as a pseudo-element so it is never content the caret can land behind or `htmlToMd` can serialise.
    - `lane-bar` — the control strip at the foot of each text, replacing "the lanes are the buttons" (197, retired at Ed's QA: clicking a clause is what `always-on-typing` means by *put a caret here*, so the gesture could not also mean *I prefer this*). A radio marked **Prefer this** / **Preferred** (272), plus ✏️ *edit this*. The rule that governs it: **a lane may carry what is about that lane, and nothing else**. The radio is the **loudest thing in the lane** (Ed, 286) — UI size at weight 600 on a 1.5px edge with a 15px dot, above the ✏️ beside it — because since 197 was retired the radio *is* the judgment, and a card whispering the one act it exists for was the wrong way round.
    - `commit row` — the card's bottom band, and the third radio (Ed, 2026-08-16, reversing 202/204/209/213). **Indifferent** sits at the left as the last of the trio — labelled, not drawn as 🤷, because every candidate carries a radio now and *neither of these* is plainly one more answer to the same question; it stays out of the lanes because it is a judgment about the *pair* (SPEC §3.2). The green **✓** sits at the right, always present and **greyed until something is chosen** — an absent button gave the row no shape and the reader no idea what finishing looked like. Skip still appears only on the 🔥 card. 🤷 has left the surface. **Every radio on a card lines up down its left edge** (Ed, 2026-08-17), locked cards included — a locked one used to keep a centred row on the argument that a lone disabled radio pushed left leaves the other end empty, which is true and does not matter: the alignment is what says the three are answers to one question.
  - `sealed record` — every entry opens one, filed ones included: the **whole field ranked**, each proposal full width in order with its win probability and whether it cleared the bar. The incumbent is not in the ranking. Where it **held**, it is the clause at the head. Where a challenger **carried**, the head is the clause as it now stands and the wording it displaced sits directly under it in a dashed band of its own, *The text it replaced* — and the winning proposal states **no wording at all**, because it *is* the head (Ed, 2026-08-17: the card printed the same sentence twice and left the one text you actually wanted inferable only from a redline inside the winner's block). Plus quorum met, the bar at the time, and what you did. Unread decisions pin themselves until you press **OK, I've seen this**; reading alone does not clear it.
  - `evidence-meter` — closeness-to-resolution as a magnitude, never a direction. Lives **only** on queue cards, where the wash's fill *is* the bar; decision cards carry no progress. Since Ed, 285 the bar sits on a **ground** of the same hue across the whole card, so the card *is* its colour and the bar says how far through that colour you are — a card had no visible right edge before, and width is the one dimension of a rail entry that carries no meaning and so has no excuse for being the one you cannot see. The ground is derived from the bar's own colour by swapping its alpha, so the two can never drift apart; and the bar's leading edge is drawn a second time in that colour, because at the bottom of the urgency scale the fill would otherwise be too close to its own ground to show an edge, and the edge is the whole of what a progress bar says.
  - `queue-wire` — for the open judgment only, the run from its entry down the gutter into every place in the charter it refers to; a patch's runs share a spine. **6px, opaque, and exactly the colour of its own queue card** (Ed, 287 and the QA of 2026-08-17), with a 10px cap at the **document end only** — the rail-end cap said nothing the card it was leaving did not already say, where the far end is the wire's actual claim, *this clause, here*. The colour is the card's wash **composited over white and painted on a white cable of the same weight**: opaque as an object, identical as a colour, which is why it also carries urgency for free — a 🔥 card's cable is the strongest on the surface. Three versions to get there and the last two are one lesson: a hue darkened toward the ink reads as a different object from the card, and the wash used *as a wash* is the right colour in the wrong medium, because a translucent cable shows the charter through it. **Match what the eye sees, not what the token says.** It is **lifted to the cards' own height** (Ed, 289a) — the same three-layer light as `--shadow-xl`, on the container so the union of underlay and colour casts one shadow rather than two of the same cable stacked. A cord lying flat between two things visibly off the page was the odd object out, and depth is the only thing this surface uses to say where something is. The colour layer is painted at **full strength inside a group carrying the alpha**, so every run, cap and spine composites exactly once: painting translucent shapes over each other doubled the alpha wherever they met, which made the landing ball darker than its cable and a patch's spine darker than the runs it crossed. 198's one-colour rule was about *kind*, which the wire was never asked to say; lifecycle is what its mark and its wash already say, so the wire agreeing adds no vocabulary. The accent is not missed: only the open judgment ever draws a wire, so its existence already says *this is the open one*. A sealed dot carries no wash, so its wire takes the fixed grey the dot itself wears. `section-toggle` — the fold triangle, mirrored in the contents rail and the document gutter.
- `race-card` — the judging surface: contested text, two candidates, A/B/indifferent/propose-C. In the UI it is the session-view's escalation state. **design/race-card.html is stale and should not be copied from** — it predates the whole current card grammar (yellow cards, per-candidate verdict buttons, "Option A/B" labels), all of which session-view has since replaced. Session-view is the only current word on card design; bringing race-card.html forward is now a rebuild, and Q70 asks whether it should exist at all.
- `composer` — **not a surface**: you compose by editing the charter (Ed, 224–241; built into session-view 2026-08-16). Its parts:
  - `always-on-typing` — every clause **and every heading** carries a caret (headings since Ed, 2026-08-17 — a section that cannot be renamed is one the charter cannot revise), and every input into one is intercepted: the charter is never edited in place, and the keystroke instead opens the `editing-card` with that character already applied. A selection may **span blocks**: the run is flattened to one string with a newline between blocks, the selection is located in *that* string, and the edit applied to it — so deleting a whole section is one edit to one piece of text, which is why it comes out as **one candidate and not a patch** (Ed, 2026-08-17). The block type travels with each origin, so a heading still reads as a heading in the lane. The caret is the accent blue, and **where it lands is announced when the surface moved it** — a short flash that shrinks onto the bar and fades — which fires on the one caret move the reader did not make: typing in the charter carries the caret off into the proposing lane of a card that has just appeared. Not on a click; a click is you putting the caret somewhere and you already know where (Ed, 2026-08-17). Its shape is not settable — CSS gives `caret-color` and nothing else (Q281). This is what makes a caret in a constitutional document safe. It also makes the **gutter mark the only way** into a decision card from the document, which is why the mark is now a 24×22 target rather than a bare glyph (Ed, 224).
  - `editing-card` — the same `decision card` shape as everything else (Ed, 2026-08-16, closing Q275 and Q270 with it): the clause at the head, your draft as the single reply in the one box left on the surface, your rationale a field in the `sealed-speaker`'s own slot — **inside the same lifted box as the wording** (Ed, 2026-08-17): the two are one *editing surface*, because you are expected to fill in both, so they sit at one height with a hairline between rather than as two boxes at different depths — so you write the sentence in the place, and at the weight, everybody else will read it in. Propose and Cancel below. It had been two side-by-side lanes on the argument that while writing you want the original level with what you are typing; that does not survive contact — the original is one line up, your additions are **marked green as you type** (Ed, 263), and a full-width lane is a far better place to write prose than a 300px column. Free to open; the edit is spent at **Propose**, which is where the price is said in words. The rationale's placeholder reads *We should change this because…* and is drawn **out of the text flow** — as inline content it sat in the line and put the caret after it, so an empty field looked like text you could not delete (Ed, 2026-08-17). The lane preserves spaces: it rewrites its own markup on every keystroke so the green marking can follow the caret, and a trailing space collapsed to nothing in the re-render until the blocks were set `pre-wrap`.
  - `lane-controls` — the only editing controls on the surface, in the top right of the `editing-card`'s box (Ed, 2026-08-17). **B**, *I*, and a two-segment **Rich / Markdown** toggle. They were going to live in the topbar; that is the wrong home, because nothing outside an open card can be edited, so a topbar toolbar would be greyed for the whole session except the minute you are writing. A candidate's text **is** markdown — most people edit it rendered, some switch to monospace source to check the characters are exactly what they meant, and that only means anything if the characters are what is stored. Rich mode serialises back through `htmlToMd` so editing rendered never silently drops the emphasis it is showing; switching view **converts the caret offset**, because markdown mode counts the syntax characters and rich mode does not. Inline only — bold, italic, code: a charter is prose, and block structure is already carried by the run of clauses.
  - `draft-site` — a **run of adjacent blocks** — clauses, headings, or both — replaced by one piece of text. One site is **one candidate**, whatever the run's length: a patch is one judgment shown at several *separate* places, and a run is one place that happens to be several blocks long (Ed, 2026-08-17). Editing across a paragraph break joins them (Ed, 225); editing somewhere else makes a second site, and the draft becomes a patch in the making — a card at each place, one Propose, the entries cabled on the wire spine (Ed, 232, 237). One draft at a time, because there is one caret (Q266).
  - `propose-edit` — ✏️ on either lane of a decision card: start writing from *that* wording rather than from the charter's (Ed, 228). `Propose something else` survives only on a **deadlocked** race, where a bridge is the ask rather than an extra.
  - `withdraw` — on your own live proposal; returns the stake in full (SPEC §3.3a) and is the reason a green entry stays pinned.
  - Superseded with it: design/composer.html's `drafting-desk` and `arrival-bar`. `the-briefing` (heat-panel, standings-panel, camp-map, why-digest, graveyard, bridge-bar) and `dominated-account` survive but are **not yet rebuilt** — the briefing as an escalation state unrolling above the lanes, and SPEC §3.5 says it may only appear where there is no live judgment left to contaminate, so a cold-start edit gets no briefing at all.
- `gazette` — public feed of resolved outcomes; the chamber view is its ambient rendering.
- `bounty-board` — public tab of deadlocked races ranked by resolvable disagreement × salience.
- `record-builder` — closing publication: final text + the record (rankings, camps, graveyard, care map, minority map, backlog, audit log).
- `spectator-api` — strictly-public engine-core projection (gazette, live candidates, bounty board, document): the only surface spectator views may consume (Q42, backlog).
- `spectator-commentary` — optional LLM commentating view for convention spectators, fed exclusively by the spectator-api; unlike the sim's omniscient `commentator`, it sees no private data (Q42, backlog).

**Tooling:**
- `sim-harness` — synthetic-participant simulator driving engine-core; parameter sweeps against throughput, stability, bridge rate, backlog quality. `npm run evidence -w @draft/sim-harness` runs the deferred-question studies (deterministic, no network); findings live in packages/sim-harness/REPORT-deferred-evidence.md.
- `participant-api` — the blind-discipline surface (engine-core module) every participant speaks: cards, judge, submit, gazette, browse. Humans, sim personas, and personal AIs are interchangeable behind it.
- `scripted-persona` / `llm-persona` — deterministic utility-model participants (regression + welfare ground truth) vs claude-haiku-4-5 participants (realism).
- `welfare-ratio` — sim metric: (achieved − incumbent) / (optimal − incumbent) summed utility over the roster; 1.0 = utilitarian-best text found.

## Conventions

- Windows machine, PowerShell 5.1 — see global CLAUDE.md traps (no Get-Content/Set-Content rewrites, use Bash tool for gh/multi-line git).
- **Checking a mockup:** serve `design/` over localhost (a tiny node http server) and measure the DOM with the browser tools — geometry, computed styles, element counts. `file://` URLs are refused by the extension. Two traps cost real time on 2026-08-16: the automation tab runs **backgrounded**, so `requestAnimationFrame` never fires, CSS transitions don't run, `:hover` never applies, and `setTimeout` is clamped to ~1s. Anything animated must be driven by stubbing the animation helper, and hover states can only be verified by reading the CSS rule. A stalled sequence in that tab usually means rAF, not a bug.
- **Mockup fixtures:** one array of items, each carrying its own content, progress and state — never parallel literals kept in sync by hand. Content is hand-authored; `sim-harness` has no session-state exporter, and the fixture holds diffs, rationales and captions the engine has no opinion about anyway.
- No deploys or pushes without Ed's say-so.
