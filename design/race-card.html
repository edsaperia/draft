    Design notes — the race-card, fifth pass

    Desktop-first · light mode only · plain Bootstrap-style theme (visual design deferred) · card content is real output from run clubhouse-1

    Layout, top to bottom

    Verdict buttons first (sticky, always at hand), rationales directly beneath them — read both arguments before you ever see a diff, which is the natural reading order — then the two document lanes. The lanes are continuous rails running the full height of the charter: where the versions agree, a single white card sits on top of both rails; where they differ, each lane carries its own card. The rail peeking out around the spanning cards keeps the two-versions structure legible even through long stretches of agreement.

    Long rationales

    Mostly a non-problem, by constitutional design: the engine caps rationales at 300 characters (rationaleMaxChars), so two side-by-side panels never grow beyond a few lines. The cap is a mechanism feature — rationales are pitches, not essays — and the UI leans on it rather than adding truncation machinery. If the cap ever rises, these panels grow naturally and the buttons stay sticky above them. Since judges read both rationales before scrolling to the diffs, they sit at the top, full-width, never clamped.

    Comparison modes, inside the split cards

    • Fair copy — clean final text. Default for wholesale rewrites: the split already locates the difference.
    • Marked up — amendment style against the current text (struck deletions, green insertions). Default for small patches (Keys card).
    • Differences — dims what both versions agree on inside the split; highlights in blue only where they disagree with each other.

    Color rule: green/red = versus the current text; blue highlight = versus each other. When both candidates replace a paragraph, the outgoing text appears at the end of the spanning card above the split, labelled "currently — both versions replace this."

    Non-contiguous patches (cards 4 and 5)

    Card 4: one proposal, two sites (the Treasurer rename). Card 5: one proposal, four sites scattered across the whole charter (a copy-edit sweep) — the lanes split and rejoin four times, and the join-split rhythm shows the patch's footprint at a glance. Badges count the sites; the verdict buttons speak once for the whole patch. If judges chronically want to split a patch, it should have been two patches — surgery's job (P3), not the card's. Beyond a handful of sites, the change ledger (adds / drops / keeps, a P3 feature) becomes the primary representation with the sites as its receipts.

    New sections (card 6)

    A patch can create text where none existed. The insertion renders at its position in the document: Version A's lane carries the new section (heading and body all-green in Marked up), and Version B's lane renders absence explicitly — a dashed card saying the charter continues unchanged — rather than showing nothing, which would read as agreement. Deletion of a whole section is the mirror image: a dashed "this section is removed" card on the proposing side.

    Diagonal (salience) cards — reframed

    Why they exist: attention is the session's scarcest resource, and the router needs to know which fights matter — to order feeds, rank the bounty board, and weight the closing record. That importance is measured the same way everything else is: pairwise, by asking. A diagonal card compares two open disputes, not two texts — you can dislike both current leaders and still have a clear answer about which question deserves the room's attention. Card 5's copy now says this explicitly, and shows each dispute as a section name first, with the current leading text as a subordinate illustration. Whether they also need stronger visual distinction (a tint) is parked as QUESTIONS #46.

    What is deliberately absent

    • No authors. Sealed until close; rationales labelled unsigned. Mo's spelling ships exactly as submitted.
    • No standings, counts, or direction. A/B order randomised per serve. (Proposal counts per dispute, shown on diagonal cards, are public magnitude — like the sort tabs — never direction.)
    • The bar is public, race evidence is not. The adoption bar in the navbar is a function of the clock, identical for everyone.
